# Release verification

Release files are published with SHA-256 checksums and GitHub artifact attestations. Verify both before using a downloaded installer or archive, especially because the free Windows and macOS packages are not backed by a paid platform-signing identity.

## 1. Download from the official release

Use only files attached to a release in:

```text
https://github.com/smarley2/insulation-coordination-calculator/releases
```

Download the desired artifact and the accompanying `SHA256SUMS` file into the same directory.

## 2. Verify the SHA-256 checksum

### Linux

```bash
sha256sum --check SHA256SUMS --ignore-missing
```

### macOS

```bash
shasum -a 256 -c SHA256SUMS
```

### Windows PowerShell

Find the expected value for the downloaded filename in `SHA256SUMS`, then run:

```powershell
Get-FileHash .\insulation-coordination-0.1.1-windows-x86_64-setup.exe -Algorithm SHA256
```

The computed value must exactly match the value published in `SHA256SUMS`.

## 3. Verify the GitHub artifact attestation

Install or update the GitHub CLI, authenticate if required, and run:

```bash
gh attestation verify <downloaded-file> \
  --repo smarley2/insulation-coordination-calculator
```

Examples:

```bash
gh attestation verify insulation-coordination-0.1.1-linux-x86_64.AppImage \
  --repo smarley2/insulation-coordination-calculator

gh attestation verify insulation-coordination-0.1.1-macos-arm64.dmg \
  --repo smarley2/insulation-coordination-calculator
```

A successful verification confirms that GitHub can associate the file digest with provenance generated by this repository's release workflow. It does not replace engineering validation, malware scanning, operating-system security checks, or review of the project's source and release notes.

Attestations are generated only for tagged releases. Artifacts produced by a manually dispatched, untagged workflow run are intended for maintainer testing and are not published as official releases.

## Failure handling

Do not run a file when:

- its checksum does not match;
- attestation verification fails for an official tagged release;
- it came from a third-party mirror or an issue attachment;
- the filename or version differs unexpectedly from the release page.

Report release-integrity concerns privately according to [`SECURITY.md`](../SECURITY.md). Do not publish potentially exploitable supply-chain details in a public issue before coordinated review.
