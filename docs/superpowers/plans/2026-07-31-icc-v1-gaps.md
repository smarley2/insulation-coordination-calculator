# Insulation Coordination Calculator — V1 Gap Closure Plan

**Date:** 2026-07-31
**Branch:** `feat/icc-v1`
**Source:** Review of `docs/superpowers/specs/2026-07-30-insulation-coordination-calculator-design.md`, the v1 task plan, the SDD ledger, brainstorm artifacts, and the implemented source tree.

## Why this plan exists

The design spec and v1 task plan enumerate five desktop pages and several workflows. A code review found the **calculation engine, rules importer, audit, report, and grouping are built and tested**, but several **UI workflows from Tasks 12, 13, 14 are only partially implemented**. This plan closes those gaps so an engineer can actually use the app end-to-end (project → pair inputs → calculation review → report) and maintain a rules package from PDFs.

## Verified implemented (no work needed)

- Domain models, `.icproj` persistence + migration, `.icrules` archive + validation + audit + importer (`identify`/`extract`/`approval`/recipes).
- Calculation engine (Part 1 + Part 4, clearance/creepage/high-frequency/altitude), grouping + splits, full trace.
- Report model, Jinja2 LaTeX, offline Tectonic compiler (fontspec fix landed), demo report script.
- Main window navigation (`Project` / `Pairs` / `Report`), project defaults + metadata + net-class editing.
- Rules Manager: approved `.icrules` import, full audit tree + search + CSV/JSON export.

## Verified missing (gaps to develop)

### Gap 1 — PDF extraction review UI (Task 13 Step 5)
The importer produces a draft with manual review items (114 items for real PDFs), but there is **no UI to review/correct/approve them**. `RulesManagerWindow.set_draft()` lists items and has an "Approve reviewed draft…" button, but `approve_draft` requires every review item resolved via `record_correction` + `review_resolutions`, which no UI performs.

**Work required:**
- Per-item review panel: for each `ImportReviewItem` (table/formula/mapping/raw_cell) show `semantic_id`, source reference, expected contract, and the extracted value/grid.
- A correction editor for each item (override extracted value, confirm table/formula/mapping, resolution checkbox + notes) that calls `record_correction(draft, changed, actor=..., notes=..., resolve=(item,...))`.
- Optional QtPdf source-page viewer beside extracted values (guard import; skip cleanly when `PySide6.QtPdf` unavailable).
- Approval form: notes + approver; disable "Export Approved Package" until all review items resolved and `approve_draft` passes.
- Tests: `tests/ui/test_rules_manager_review.py` — exercise a resolved draft round-trip with `record_correction` + `approve_draft`, verify the button gates.

### Gap 2 — Complete pair editor (Task 12 Step 4)
`PairEditor` only exposes RMS, steady peak, recurring peak, temporary peak, frequency, and insulation type. Missing: impulse (no widget), field/geometry, altitude, pollution, construction, CTI/material group, electrode radius, special-condition flags, notes, and an N/A (with justification) button per voltage. Missing Default/Override markers on every inheritable field.

**Work required:**
- Add input widgets + setters for: impulse, field condition, altitude, pollution degree, construction type, CTI/material group, electrode radius, conventional-construction-assumption flags, notes.
- Add a per-voltage "Not applicable (justify)" toggle + justification field for the four voltage inputs.
- Add visible Default/Override provenance labels on frequency, impulse, insulation, field, altitude, pollution, construction, CTI, radius.
- Tests: extend `tests/ui/test_pair_workflow.py` (or new `test_pair_editor_fields.py`) to set each field and assert the updated `PairCase`; assert N/A + justification state.

### Gap 3 — Calculation review page (Task 12 Step 5)
`CalculationReviewPage` only lists result summaries and group ids. It must show candidates, formulas, substitutions, source references, warnings, errors, and group membership; recalculate immediately after valid changes; clear stale results after invalid changes; allow split only.

**Work required:**
- Render per-result: clearance/creepage candidates (candidate id, stress, distance, semantic rule id, reason), governing selection, altitude note, trace steps (symbolic + substituted), warnings, verification requirements, group membership.
- Wire recalculate-on-change: pair editor emits `pair_changed` → PairPage recomputes and passes results to `CalculationReviewPage` (already wired partially); invalid change clears stale result.
- Add split control using `split_group`; reject merge via `merge_groups` when signatures differ.
- Tests: new `tests/ui/test_calculation_review.py` asserting candidates/text/warnings/errors appear and stale results clear.

### Gap 4 — Report page group controls + preview (Task 14 Step 3)
`ReportPage` shows automatic groups and a generate button but no allowed-split controls, no group/result preview, and no merge-reject. It recalculates on load (good).

**Work required:**
- Add per-group split UI (select group + pair subset → `split_group`, persist `GroupSplit` to `Project.group_splits`).
- Add validation summary listing complete vs blocked pairs (present but minimal); show group membership and allow splitting from Report page.
- Preview: list of generated artifacts already present; add a "blocked pairs" section and a preview of groups before export.
- Tests: extend `tests/ui/test_report_page.py` (or new `test_report_group_controls.py`) asserting split persists and cross-signature merge is rejected.

### Gap 5 — Finish pair workflow integration from Rules import (Task 14 Step 1 linkage)
Rules Manager approves/imports a package, but that package is not pushed back into the running project. `PairPage.rules_changed` exists and `MainWindow._on_rules_changed` handles it, but `RulesManagerWindow` does not emit on approve/import and MainWindow doesn't open Rules Manager read-write.

**Work required:**
- Add a `RulesManagerWindow` signal (e.g. `package_activated(object)`) emitted on `import_package`/`set_package`; MainWindow connects it to `load_rules`.
- After importing an approved package, refresh Pair page + Report page and revalidate project rules mismatch.

## Execution order

1. Gap 1 (rules review UI) — most impactful for the "your PDFs → .icrules" goal.
2. Gap 2 (pair editor completeness) — enables real data entry.
3. Gap 3 (calculation review) — shows the audit evidence.
4. Gap 4 (report group controls).
5. Gap 5 (rules → project wiring).

Each gap: write failing tests, implement, `uv run ruff check .`, `uv run mypy`, run `pytest -m "not private_standard"`, focused commit.

## Out of scope (documented but not developed in this pass)

- QtPdf source-page viewer (kept optional behind import guard).
- Public macOS signing/notarization and real Windows installer validation (Task 15 release gates).
- Tectonic manifest hash verification at startup (placeholder hashes).
