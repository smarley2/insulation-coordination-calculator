> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extract the last five IEC 62477-1:2022 required source items, empty the deferred set, and demonstrate Issue #34's Definition of Done end to end.

**Architecture:** Clause-derived procedures and decisions in a new `recipes/iec62477_1_2022/procedures.py`, registered through the recipe's `clause_projectors`. The test cross-reference matrix is a `comparison_only` grid used to validate every procedure's classification. No new mechanism.

**Tech Stack:** Python 3.12, pydantic v2 frozen models, pdfplumber, pypdf, pytest, ruff, mypy, uv.

**Design spec:** `docs/superpowers/specs/2026-08-10-iec62477-slice-e2-design.md`

**Why first:** E2 adds a second cross-standard check. Today a check ID is a suffix of the semantic ID it compares, so `inventory_report`'s route matching (`_covers`) reads a check as a route of the rule, and an unresolved check would block the rule it exists to support.

In `test_package_expectations.py`:

```python
def test_a_check_identifier_is_not_a_route_of_the_rule_it_compares() -> None:
    """A check supports a rule; it is not one of that rule's routes.

    While a check identifier is a suffix of the semantic ID it compares, an unresolved
    check blocks the very rule it exists to support.
    """
    expectations = package_expectations(RECIPES)
    for check_id in expectations.proven_mapping_ids:
        for rule_id in expectations.table_rule_ids | expectations.projected_rule_ids:
            assert not check_id.startswith(f"{rule_id}.")
```
