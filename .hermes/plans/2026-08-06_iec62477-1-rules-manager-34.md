# Extend Rule Manager for IEC 62477-1:2022 (#34) — Implementation Plan

> **For Hermes:** execute task-by-task. Scope: the **public mechanism** (committable, testable). The **private recipe extraction** of licensed IEC table values is intentionally NOT in this branch's commit scope — licensed content cannot be committed publicly (repo README + issue §Public/private separation). It is a follow-up that runs through the `.icrules` approvals workflow against the licensed PDF.

**Goal:** Make DecisionRule/ProcedureRule/GuidanceRule first-class typed rules so the Rule Manager can import, review, approve, audit, and (later) execute IEC 62477-1:2022 packages — IEC 62477-1:2012 rejected.

**Architecture:** Bump `.icrules` schema 2→3 with new typed rule collections + two new expression nodes (SquareRoot, Power) for RMS↔peak. Extend archive members, validation (incl. 2012 rejection + package completeness gates), audit inventory, and the Rules Manager audit tree/search. All fixtures stay synthetic.

**Tech Stack:** Python 3.12, Pydantic v2, Decimal-only arithmetic, pytest + hypothesis, mypy strict, ruff. Gates: `pytest` (coverage ≥80), `ruff`, `mypy --strict`.

---

## Scope decision (Ponytail — stop at the rung that holds)

The issue's acceptance criteria split into:

- **Public mechanism (THIS branch)** — schema, expression ops, evaluators, validation, archive, audit, Rules Manager tree/search, synthetic fixtures, tests. Fully testable in CI without licensed content.
- **Private recipe + review UI for real Tables 2/3/7/26-30 (FOLLOW-UP)** — reproduce in the private `.icrules` approvals workflow; requires the licensed PDF + a maintainer review step; not committable. The schema/audit plumbing this branch adds is precisely what that step needs, so does not block later project issues.

## Task 1: Schema v3 (`src/insulation_coordination/domain/rules.py`)

- Add expression nodes `SquareRoot` (`value: Expression`), `Power` (`base`, `exponent`); add to the `Expression` union + recursive-rebuild tuple.
- Add `RuleCondition` (wraps a boolean `Expression` + `summary`), `DecisionInput` (name + categorical `domain`), `DecisionOutcome` (id, label, `requires_evidence`, `warnings`), `DecisionRow` (`match: dict[str,str]`, `result`), `DecisionRule` (id, inputs, outcomes, rows, applicability `RuleCondition`, source).
- Add `ProcedureRule`, `GuidanceRule` per the issue's proposed fields.
- Bump `RULE_SCHEMA_VERSION = 3`, `IEC_IMPORTER_VERSION = "iec-pdf-3"`.
- `RulePackage` += `decisions`, `procedures`, `guidance`.
- Validate in-model: decision `match` keys ⊆ input names, `result` ∈ outcome ids, row match dicts unique, procedure/gudiance ID non-empty.

## Task 2: Evaluators (`src/insulation_coordination/rules/evaluator.py`)

- In `_Evaluator.evaluate`: add `_square_root` (Decimal `.sqrt()`) and `_power` (`base ** exponent`, exponent must be integral/rational scalar; unit rules) — deterministic, no code execution, rendered trace.
- Add `_walk`-safe `_expression_children` in `validation.py`/`audit.py` too for the two new nodes.
- New public: `evaluate_applicability(condition, variables, tables) -> bool` and `evaluate_decision(rule, inputs, variables, tables) -> DecisionResult` (typed match + trace + source) — or thin functions reusing `evaluate_formula`.
- Keep `bool` unit semantics consistent with existing `Compare`.

## Task 3: Archive (`src/insulation_coordination/rules/archive.py`)

- `CORE_MEMBERS` += `decisions.json`, `procedures.json`, `guidance.json`; update `_core_member_payloads`, `load_rule_package`, checksum coverage, `write_rule_package`.

## Task 4: Validation (`src/insulation_coordination/rules/validation.py`)

- Handle SquareRoot/Power in `_expression_children`/`_walk_expression`.
- New checks:
  - unique decision/procedure/guidance IDs; decision rows valid; every decision/procedure/guidance has meaningful source; applicable source references.
  - `edition_supported`: any approved IEC package whose source is IEC 62477-1 must be edition `2022`; `2012` → FAIL (explicit rejection).
  - `package_completeness`: for approved IEC 62477-1:2022 packages, require ≥1 decision, ≥1 procedure, ≥1 guidance and presence of DVC/earthing/OVC/dielectric semantic groups (add only when the package is an IEC 62477-1 package — don't regress existing IEC 60664-1/synthetic packages).

## Task 5: Audit (`src/insulation_coordination/rules/audit.py`)

- `AuditInventory` += `decisions`, `procedures`, `guidance` (+ counts); extend `_source_references` + `build_audit_inventory`; export JSON/CSV.

## Task 6: Rules Manager UI (`src/insulation_coordination/ui/rules_manager.py`)

- `_SECTIONS` += "Decisions", "Procedures", "Guidance", "Standards compatibility" (before Validation; update hardcoded topLevelItem indices and the `_add_*_items` index numbers).
- Populate each new section from the inventory; standards-compat section shows edition per source document + completeness.
- Search already traverses the whole tree (`_collect_audit_lines`) so new items are found; extend `_collect_references`.

## Task 7: Synthetic fixtures + tests

- `tests/fixtures/synthetic_rules.py`: add a synthetic DecisionRule (DVC→protection outcome), a ProcedureRule (impulse test), a GuidanceRule, and a formula that uses `SquareRoot` (RMS→peak) so the evaluator is exercised. Synthetic values only.
- Tests: `tests/rules/test_evaluator.py` (+sqrt/power/decision/applicability), `test_archive.py` (new members round-trip), `test_audit.py` (new inventory), `test_validation.py` (2012 rejection, completeness gate), `test_importer.py`/fixtures intact.

## Risks / tradeoffs / open questions

- **Backward rejection is intentional**: schema 2 archives are rejected on load (already the behavior on version mismatch); existing `iec60664-1:2020` private packages must be re-imported at v3 — matches the repo's existing regenerate-on-bump pattern.
- **Do NOT add the actual IEC 62477-1 table values** in this branch — that is the licensed/private follow-up.
- Later issues can consume typed decision/procedure results without embedding IEC logic in UI code (acceptance criterion 10).
